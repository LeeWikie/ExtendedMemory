# Paperclip Memory Organization for ExtendedMemory

基于 Paperclip 的 `para-memory-files`，供后台记忆处理模型维护一份完整、可直接用于下一次会话的常驻记忆。上游版本、许可和适配差异见 [Paperclip 来源与适配](references/paperclip.md)。

## 运行约定

- 你是独立运行的后台微型 Agent。调用方提供新增对话及其来源标识、原始时间、收集时间、当前时间与时区，以及整个常驻记忆的 token 预算。通过文件工具按需读取当前 `MEMORY/`，无需每轮重新接收或输出整份记忆。
- 整理在后台异步进行。此 Skill 只供后台模型加载，主会话 Agent 不承担记忆管理，也不需要记忆读写、检索或整理工具。
- 通过专用工具直接读写真实的 `MEMORY/`。你可以新建文件和目录、局部编辑、移动、重命名、合并和删除；没有候选版本、宿主内容校验或发布环节。工具仅允许访问 Memory 文件，不提供 shell 或其他主会话工具。
- 新会话全量注入开始时 `MEMORY/` 的全部正文。当前会话继续使用启动时的快照，包括上下文压缩后的恢复。
- 默认总预算约为 50,000 tokens，由调用方配置并用实际 tokenizer 计量，包含文件路径、标题和注入包装；每个文件共享这个预算。预算充裕时保留有价值的具体事实、原话中的限制条件和变化经过，无需沿用较小预算下的压缩程度；也无需为了填满预算增加内容。
- 原始对话和历史后台会话由调用方保存在记忆状态目录，后台会话不进入 pi 的常规历史列表。当前仍需供主 Agent 使用的记忆必须写入 `MEMORY/` 正文，不能只留下指向未注入内容的索引。
- 同一前台会话的后台上下文持续追加，已有读取结果可辅助定位。每轮先检查相关文件的当前内容再修改，其他会话可能已经更新它们。小变化用 `memory_edit` 精确替换，避免重写无关文件。中断不会回滚已完成的文件修改；重试时先检查实际文件，完成剩余工作，不重复套用旧改动。
- `memory_list` 列出文件，`memory_read` 分段读取，`memory_search` 定位相关原文；`memory_write`、`memory_edit`、`memory_mkdir`、`memory_move`、`memory_remove` 直接整理文件。`memory_tokens` 计量所有 Markdown 及注入包装，预算由你按本 Skill 管理，工具不会因内容分类或预算超限而要求宿主审批。

## 从 Basic 开始

初始结构保留三个泛概念，并增加负责时效性记忆的 `Recent`：

```text
MEMORY/
├── IDENTITY.md
├── MEMORY.md
├── USER.md
└── Recent.md
```

`IDENTITY` 承载助手自身的身份与定位；`MEMORY` 承载交流和经历中值得延续的记忆；`USER` 承载关于用户的综合理解。依据内容决定具体归属，不预设下级主题、固定栏目、文件数量或各文件配额。

`Recent` 是必需的近期状态正文，可以是 `Recent.md`，也可以按同样的分解规则生长为 `Recent/Recent.md` 与下级内容。没有可信近期依据时明确写明尚未确认，不编造位置、行程或待办。

这些是生长的起点。一个主题可以先是一段正文，随后成为文件，再成为带有综合摘要和下级内容的目录。

## 整理事实

先阅读当前记忆，再将新增材料与已有事实对照。保留能独立理解的事实，以及理解它所需的时间、适用范围、原因和不确定性。来源中的要求、示例和模型推测应按其原本性质理解，不能自动变成已发生的事实。

- 新信息补充同一件事时，合并有效细节；同义复述无需产生新的记忆。
- 明确的新状态替代旧状态时，更新当前正文，并在整理记录中标明被替代的内容和依据。需要理解变化过程时，在正文保留简短的时间关系。
- 一次临时变化不自动推翻长期偏好。无法消解的冲突应保留范围或不确定性。
- 内容可以同时关联多个主题。选一个合适的位置存放完整事实，在其他位置保留必要关系，避免复制整段内容。
- 无新价值时可以不修改。不要为填满文件或满足数量要求制造内容。

## 人称与指代

记忆正文尽量使用客观实体名称与明确的关系陈述。先识别说话者及原话所指主体，再整理事实；用户、助手、第三方及转贴材料中的说话者不能混为一人。用户直接说“我”通常指用户，助手回答中的“我”指助手，引用、转贴、示例中的第一人称属于其原有语境，不能自动转写成用户经历。

“本机”“此电脑”“这台设备”等指代必须按来源会话当时的主体、主机和明确证据消解，尽量写为已确认的设备名称。用户明确指定当前“此电脑”对应某台设备时，将该映射保留在适用的当前环境关系中；这不改变其他来源会话里的指代。历史远端服务器、另一台电脑或他人设备中的“本机”不能映射为当前主机；无法确认时保留“该来源会话所用设备，具体型号待确认”，不凭设备列表猜测。除了有清晰适用范围的当前指代约定，其他设备、人物、地点与事件使用客观陈述。

调用方可提供 `source.collectionContext`，其中 `hostname`、`cwd`、`platform` 是收集来源时实际的主机名、工作目录和平台。这是采集环境，不是历史消息原设备的证明；导入、恢复或跨设备复制的会话可能讲述另一台设备。只有消息自身或同一来源中明确的主机依据才能把指代锚定到实体，不能仅凭采集环境将旧消息中的“此电脑”改写成当前采集主机。老任务未提供该字段时仍可整理，缺少的来源设备信息保持未知。

## 维护 Recent

每次整理都将 `Recent` 与调用方的当前时间对照。它优先承载近期 session 中用户直接输入的近况、位置变化、正在做的事、短期计划、尚未解决的事情，以及影响接下来交流的限定条件。不要仅因这些内容不够长期就全部丢弃，也不要将整个近期对话逐条复制进去。来源标识与原始时间保留在正文需要追溯的关键事实旁，完整来源仍由目录外的审计记录保留。

- 优先使用最近的用户直接陈述。助手建议、猜测或任务计划不能当作用户已确认的现状；实际工具结果也要与用户原话区分。
- 区分当前状态、此前状态和计划状态。事实时间采用消息的 `timestamp`；`capturedAt` 和任务的 `createdAt` 只是收集时间，历史导入不能因此变成刚发生的事。缺少原始时间时标明未知，不能用导入日期代替。
- 新位置或行程状态有明确依据时更新当前状态。预算允许且有帮助时，保留简短前情与变化关系；长期居住地不应被一次出行覆盖。晚到的旧消息不能反向覆盖已确认的较新状态。
- 对短暂状态写明最后确认时间、适用时段或有效期。对乘车、临时位置等短暂状态，距最后确认已经过久而没有新依据时，改写为“最后确认于……，当前状态待确认”，不能一直声称“现在正在……”，也不能推测已经抵达。明确日期的计划在日期过去后只能标为已过期、结果待确认，不能自动标成完成。
- 在近期状态有依据地结束、改变或失去当前意义时，更新或移出 Recent；有长期价值的内容归入相关主题，同时保留必要前情。稳定关系、偏好和持续约束不能仅因未近期提及就过期。
- 不设置统一的保留天数或固定各项配额。由事件持续时间、影响、是否未解决和来源可信度判断时效；容量充足时可以保留较丰富的近期经过，并继续给当前状态清晰的位置。

下面仅说明更新方式，不是关于当前用户的事实：若材料明确说先前在武汉，而较新的用户原话是“我现在在前往青岛的火车上”，可在对应时间下记为“最近在武汉；最后确认正乘火车前往青岛”。只有材料另有“出差”的明确依据时才写“前往出差地点”；不能从目的地或乘车行为猜测目的。此示例本身不得写入用户的 Recent。

## 何时考虑独立组织

沿用 Paperclip 的三个主要信号：同一实体反复出现、与用户有直接关系、对用户足够重要。在本项目中，它们触发一次组织判断，由模型决定合适的粒度。

| 信号 | 需要判断的内容 |
| --- | --- |
| 同一实体或主题在材料中出现三次及以上 | 是否已经形成持续、相互关联的内容；同一证据的重复引用不算新增出现 |
| 与用户有直接关系，或影响重要决定 | 是否值得立即独立维护；不要求先积累到三次 |
| 某段内容持续增长，混入多个可区分主题 | 是否需要独立文件，或进一步创建目录并重新归纳 |
| 修改一处时经常牵连不相关内容，或多处重复 | 是否应拆分、迁移、合并或重新命名，使归属更清楚 |

容量和重要性都是判断依据。一次提及也可能重要；内容很多也可能仍是一个连贯整体。不要只按 token 数切块。

## 怎样分类和分解

从实际材料归纳主题。先尝试在已有正文内归并；当一组内容有清楚的共同含义，独立维护能改善理解或更新时，再建立文件。需要同时保留整体理解和多个可独立维护的方面时，将该文件升级为目录。

采用一致的升级方式：`X.md` 变为 `X/X.md`，原文件位置移除，新的同名文件承担该目录的综合摘要，下级文件由内容决定。递归应用同一规则。已有目录名称应保持稳定，只有含义确实变化才重命名。

拆分时同时重写父级和子级：

1. 为每个新分支说明它涵盖什么、与相邻分支如何区分。
2. 将完整事实放到合适的下级文件，保留时间、限定条件和重要关联。
3. 从整理后的内容重新写父级摘要，表达整体理解与跨分支关系；父级不能只剩文件链接，也不应重复所有细节。
4. 核对旧内容的去向。单纯调整结构不应丢失有效信息；压缩或退出常驻的决定应另外说明。

如果拆分只能得到空目录、一句话文件，或无法解释分支边界，就保持原结构。已失去独立意义的分支可以合并回父级。没有新的实质依据时，不要反复拆分和合并同一组内容。

## 摘要与常驻预算

沿用 Paperclip 从有效事实重写摘要的做法。事实变化时更新有关正文及父级摘要；全量复盘时检查整体归纳、跨文件重复和过时内容。周度复盘可以作为调用方的初始调度策略，此 Skill 本身不创建定时任务。

约 50k tokens 是整个记忆集合的预算，Recent 也使用同一个总预算。拆目录不会增加预算，也不会因文件更深而减少注入内容。

空间紧张时，先消除重复与失效表述，再压缩冗长叙述。根据长期价值、当前影响和反复出现的程度分配篇幅；保留会改变理解或行动的关键细节。需要退出常驻的低价值细节应在整理记录中单独说明，不能声称压缩完全无损。

时间和实际使用可以辅助排序。全量注入不代表每条记忆都被使用；没有可观察依据时不要增加使用计数。稳定身份、持续关系和仍有效的约束，不因一段时间未提及就自动失效。

## 交付和检查

修改直接写入 `MEMORY/`，完成后用简短文字说明修改和迁移理由、被替代或退出常驻的内容，以及 `memory_tokens` 的实际结果；无变化时简短说明即可。调用方把这段说明和来源记录保存在记忆状态目录。不要返回整份目录内容，不需要 JSON 候选树，也不等待宿主发布。缺少计量结果时标记为未验证，不能估算后声称达标。

结束前自行检查：

- 全量注入当前目录后，记忆可以独立理解，不依赖主 Agent 再检索隐藏详情。
- 新旧事实关系清楚，推测与确认信息分开，关键限定条件和跨主题关系仍然存在。
- `Recent.md` 或 `Recent/Recent.md` 存在；近期用户原话得到充分考虑，当前、此前和计划状态分开，短暂状态有最后确认时间，示例未成为用户事实。
- 拆分后的父子内容形成整体，分类来自实际材料，迁移没有意外遗漏。
- 用 `memory_tokens` 确认总预算；超出时继续归并、压缩和取舍。文件工具只负责文件系统权限边界，不代替你的整理判断。

依据不足时保留不确定性，不推测补全。整理尚未完成时说明剩余项，下一次读取实际文件继续处理。主会话无需等待整理完成。
